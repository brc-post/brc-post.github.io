BRC Post changes
================
Version numbers: last number for fixes and wording, middle number for new
features, first number for changes to file formats or the security model.
Test builds carry "-test.N" and are never published. BRC Post is not live.

0.6.0 (in progress)
  - test.4: "it just works" mailbox (Patrick, Oct 31). Create my mailbox makes
    one right here: choose a password, the locked backup downloads by itself,
    and this device can remember the LOCKED copy, so next time you only type
    your password (Unlock). I already have a mailbox opens a backup file (or
    its paper code, behind a link) and can remember it too. Remove from this
    device needs a second press. Your mailbox link (#to=address) with Share
    and Copy; opening it starts a letter with the address and its picture.
    One "Paste it here" box on the home screen: letters (asking for the
    password if needed, then opening), signatures, receipts, mailbox links,
    mailbox backups; an address is explained as public; coin keys refused.
    Sealed letters get a Send button (share sheet). Plain words: mailbox,
    password, backup; "Post seals it".
  - test.3: pasting a 64-character code into the mailbox key box (an address
    looks exactly like a private key) now says so and points to the
    brc-mailbox-key-….json file, instead of only "a key that can hold coins".
  - test.2: published for testing at https://brc-post.github.io (its own origin);
    test builds ask search engines not to index it (robots tag and robots.txt).
  - test.1: BRC Seal is now BRC Post (Patrick, Oct 31): the name grows into the
    BrowserCoin mail service. Same envelope-and-seal mark with a BRC POST
    wordmark; the BRC Works line reads "Vault keeps it · Post sends it ·
    Pulse checks it". Only names changed: the letter, postmark and signature
    formats are untouched, so everything made under the old name still opens
    and checks. Earlier entries below use the new name.

0.5.0 (in progress)
  - test.4: the BRC Works addresses are filled in: release address 7ccb496c…caa00,
    giveaway mailbox b4b31b73…9997b, prize pool 41210e34…758d1 (made in BRC Vault
    by Patrick, Oct 31).
  - test.3: points to BRC Vault's new New wallet tab for mailbox keys.
  - test.2: the check view on BRC Pulse is now called "Check it"; every
    pointer to it says so.
  - Fixes from the Fable 5.1 security review (Oct 31): every purpose has
    its own phrase prefix (files, messages, links, releases, giveaway lists);
    only the signer's own lock counts; locks with wrong signatures are
    refused; chain-signed messages and links are shown as not checked until
    BRC Pulse checks them, and sealing to a link needs a confirmation;
    warnings against locking someone else's phrase; coin material refused
    before it is parsed; address picture from SHA-256; more look-alikes.
  - Giveaway: sign the entry list and draw round on the chain before the draw.
  - No coin keys: BRC Post stops taking wallet files and private keys.
    Mailbox keys (from BRC Vault or made here) open letters and sign.
  - Sign on the chain: prove a coin address with the official app's
    hash-locked payment, no key pasted anywhere.
  - Link a mailbox to a coin address, on the chain.
  - Official BRC Works addresses by name (src/official.js, shared with
    BRC Pulse); look-alikes are flagged, and refused as a seal-to address.
  - Release messages for postmarking every published file.
  - The version is shown in the footer next to the build code.

0.4.0
  - Design direction D, postal language and motion.
  - Postmarks (file fingerprints on the chain) with optional Lock ID.
  - Open many letters: a mailbox owner opens a whole BRC Mailbox export.
  - Giveaway entry core: address-only entries, fingerprints, drand draw.
  - Fixes from the first security review.
